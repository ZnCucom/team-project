# Lo-Fi Companion

[English](README.md) | [中文](README.zh-CN.md)

## 项目简介

Lo-Fi Companion 是一个使用 Java Swing 开发的桌面学习陪伴应用，目标是在学习或工作时提供一个轻松、舒适并具有陪伴感的环境。

应用将包含几个彼此关联的主要功能：

- 专注与任务管理，
- 虚拟桌宠，
- 基于 Spotify 的背景音乐，
- 以及基于天气变化的场景。

项目的目标是创建一个小型虚拟学习空间，让用户能够规划需要完成的事情、专注学习、播放音乐，同时获得来自虚拟宠物的简单陪伴和反馈。

第一版计划支持一个用户、一只宠物、一个轻量级 To-Do List、一个专注计时器、少量宠物对话、在条件允许时使用 Spotify 的音乐功能、天气场景，以及一个主要的 Java Swing 应用窗口。

## 核心 User Stories

### 1. 专注计时器与 To-Do List
**负责人：[Member A]**

作为一名学生，我希望能够管理待办任务并使用专注计时器，从而安排需要完成的事情，并追踪自己的学习进度。

第一版计划包含：

- 可设置时长的专注计时器，
- 开始、暂停、继续和重置控制，
- 已完成专注 session 的记录，
- 以及一个用于管理学习任务的轻量级 To-Do List。

To-Do List 的具体设计将在后续进一步完善。第一版可能支持添加任务、将任务标记为已完成以及删除任务等基础操作。

完成一次专注 session 后，虚拟宠物还可以显示一句简短的鼓励。

---

### 2. 桌宠互动
**负责人：[Member B]**

作为一名用户，我希望能够给虚拟宠物起名、与它互动，并随着亲密度提升解锁新的对话，从而在学习时获得陪伴感。

第一版将允许用户：

- 给宠物起名，
- 与宠物进行简单互动，
- 提升 friendship progress，
- 根据 friendship progress 解锁不同的对话内容。

当用户完成一次专注 session 或完成一个任务时，宠物也可以做出简单回应。

---

### 3. Spotify 音乐集成
**负责人：[Member C]**

作为一名用户，我希望能够连接 Spotify，并直接从应用中控制学习时播放的音乐，从而无需离开当前学习界面就能调整自己的学习氛围。

计划中的 Spotify 集成功能可能包括：

- 连接 Spotify 账户，
- 查看当前正在播放的曲目，
- 访问指定的音乐或播放列表，
- 控制 Spotify API 所支持的播放操作，例如播放、暂停、切歌和音量，
- 并在应用重新打开时恢复适合保存的音乐偏好。

最终能够实现哪些 Spotify 功能，将取决于 Spotify Web API 的功能、认证要求以及访问限制。

如果 Spotify 无法使用或无法连接，应用的其他功能仍应保持可用。必要时可以加入一个简单的备用音乐方案。

---

### 4. 天气场景
**负责人：[Member D]**

作为一名用户，我希望能够选择一个城市，并让房间场景根据该城市当前的天气变化，从而让学习环境与现实世界产生联系。

第一版将允许用户：

- 输入或选择城市，
- 通过外部天气 API 获取当前天气，
- 将天气映射为少量场景类型，例如晴天、多云、下雨或下雪，
- 显示对应的房间背景。

如果天气数据获取失败，应用将显示默认场景，同时保证其他功能仍然可以正常使用。

## 功能分工

每位组员主要负责应用中的一个完整功能区域，包括对应的界面、应用逻辑、Clean Architecture 组件以及相关测试。

| 组员 | 主要功能区域 | 主要职责 |
| --- | --- | --- |
| [Member A] | 专注与任务管理 | 专注计时器、专注 session 记录、To-Do List、相关 UI 和测试 |
| [Member B] | 桌宠互动 | 宠物状态、亲密度系统、对话系统、宠物 UI 和测试 |
| [Member C] | Spotify 音乐集成 | Spotify 认证与 API 集成、播放控制、音乐状态与偏好、相关 UI 和测试 |
| [Member D] | 天气场景 | 天气 API 接入、天气到场景的映射、天气 UI、错误处理和测试 |

共享的应用组件、功能整合以及整体设计决策将由整个团队共同讨论和 review。

## 功能之间的联动

这些功能应当组成一个完整应用，而不是四个彼此完全独立的小程序。

例如：

- 完成一次专注 session 后，可以提升宠物亲密度并触发一句鼓励对话，
- 完成一个 To-Do 任务后，也可以触发宠物的简单回应，
- 天气系统可以改变房间背景，
- 用户使用计时器或 To-Do List 时，Spotify 音乐可以继续作为学习背景音乐。

第一版将保持这些联动简单，避免因为功能之间过度耦合而增加实现难度。

## 数据持久化

应用将使用 JSON 在本地保存适合持久化的用户数据。

保存的数据可能包括：

- 宠物名称，
- friendship progress，
- 已完成的专注 session，
- To-Do List 数据，
- 适合保存的音乐偏好或 Spotify 相关设置，
- 音量偏好，
- 以及所选择的城市。

当用户重新打开应用时，这些信息将被恢复。

敏感的认证凭据或 secret 不会直接保存在项目仓库中。

## 计划使用的外部 API

### Spotify Web API

音乐功能计划使用 Spotify Web API。

用户完成授权后，应用可以利用该 API 获取 Spotify 信息，并控制 API 所支持的播放功能。

Spotify 相关代码将通过 interface 与应用的主要业务逻辑隔离，这样即使 API 发生变化，也不需要大规模修改其他功能。

由于 Spotify 的功能会受到认证方式、账户能力以及 API 访问限制影响，最终支持的具体音乐控制功能将在实现阶段进一步确认。

### Weather API

天气功能将使用一个外部天气服务来获取指定城市的当前天气信息。

目前具体使用哪一个天气 API provider 尚未最终确定。

天气功能同样会通过 interface 与主要应用逻辑隔离，这样未来即使更换外部天气服务，也不需要对应用的核心逻辑进行大规模修改。

如果天气数据无法获取，应用将使用默认场景。

## 第一版范围

Lo-Fi Companion 的第一版计划包含：

- 一个 Java Swing 主窗口，
- 一只虚拟宠物，
- 一个简单的 friendship 系统，
- 基础宠物对话，
- 一个专注计时器，
- 专注 session 记录，
- 一个轻量级 To-Do List，
- Spotify 集成以及有限的音乐控制功能，
- 当前天气查询，
- 几种基于天气变化的房间场景，
- 以及本地 JSON 数据保存。

项目将优先保证应用规模较小但功能完整、可靠，而不是一开始加入大量复杂功能。

---

## 第一版暂不包含的功能

以下功能目前不计划加入第一版：

- 多人模式，
- Lo-Fi Companion 自身的用户账户系统，
- 云同步，
- 多只宠物，
- 复杂剧情分支，
- 高级任务管理功能，
- 高级 Spotify 音乐库管理，
- 高级桌面悬浮功能，
- AI 生成对话。

只有在核心功能完成后，团队才会考虑是否加入这些扩展功能。
